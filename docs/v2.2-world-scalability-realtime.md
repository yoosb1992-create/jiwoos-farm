# v2.2 World Scalability & Realtime Multiplayer Foundation

This branch establishes the scaling rules for a larger Jiwoo's Farm world without changing the persistent-authority model.

## World/editor scaling

- Normal editor undo entries snapshot only the active map. Structural operations (import/reset/add/remove) may snapshot the full document.
- Terrain brush strokes are buffered locally and committed once per pointer stroke.
- Local editor drafts are stored as a small manifest plus per-map JSON records. Legacy v1 documents still load.
- Large-map terrain edge composition visits authored path/water cells instead of scanning every grass tile.
- `game/maps/chunks.ts` defines a stable 32×32 chunk coordinate contract for later camera-window loading/culling.

The current runtime already renders one map at a time. The chunk contract is intentionally a foundation: later content expansion can move map objects, collision and farm data behind chunk indexes without changing map IDs or warp contracts.

## Realtime Family presence

Persistent gameplay remains D1-authoritative. Inventory, crops, storage, money, crafting, mining and other world mutations continue through the existing Family action/state APIs.

Player pose uses a separate fast plane:

1. The browser opens `/api/family/presence/socket`.
2. The route authenticates the ChatGPT user and verifies room membership through D1.
3. Pose frames are sent every 100 ms and broadcast to connected room members.
4. Remote Phaser sprites interpolate those snapshots each render frame.
5. The client automatically reconnects the WebSocket.
6. A 1.5 s D1 heartbeat remains active as a safety fallback.

### Hosting note

The current Sites project exposes D1/R2 bindings but no Durable Object binding. The socket route therefore uses an in-process room broker as the low-latency fast path. This is useful immediately, but it is not a cross-isolate room authority. A room-scoped Durable Object should replace the broker when the hosting surface provisions a DO binding. The browser transport and `FamilyClient` API are already separated so that replacement does not require another gameplay rewrite.
