# v2.8.3 — 하나의 월드 편집기와 개인 시작 농장

기준 HEAD: `260851d3e641c3688895a5bcc46e02eff61a6936`.

## 맵이 달라 보였던 이유

기존 공식 기본 생성 함수는 공유됐지만 편집기는 IndexedDB `draft/current` 또는 이전 로컬 초안을 우선 복구했다. 게임은 이미 생성된 가족의 PostgreSQL `World.layout`을 사용했고, 게시 설계도는 새 가족 생성 때만 사용됐다. 또한 편집기의 타일 청크 변환은 게임 기본 생성과 다른 단계에서 실행됐으며, 게임에서 자라는 나무·돌·풀은 설계도 밖의 실제 엔티티였다.

이제 기본 설계도는 모든 지역을 같은 청크 형식으로 정규화한다. 서버의 `official_world_versions` 최신 게시본을 공식 편집 모드와 신규 기본 농장이 함께 사용한다. 공식 버전 1은 한 번만 생성하며 코드 배포가 기존 게시본이나 가족 레이아웃을 교체하지 않는다. 생성 시 사용한 출처/버전은 `World.sourceTemplate`에 남는다.

## 세 가지 편집 대상

- **공식 기본 월드**: 서버 게시본을 명시적으로 불러와 기기 편집 초안으로 작업한다. 개인 복제와 운영자 게시를 분리한다.
- **나만의 시작 월드**: 기기별 IndexedDB `templates`에서 고유 ID, 이름, revision으로 여러 초안을 보관한다. 5초 자동 저장, 복제, 이름 변경, 간단한 삭제 확인, JSON 입출력, 시작 농장 등록을 지원한다. 같은 초안을 두 탭에서 저장하면 revision 검사가 충돌을 알려 덮어쓰지 않는다. 이전 `current` 및 localStorage 초안은 별도 개인 초안으로 보존한다.
- **현재 농장**: 현재 기기의 농장 소유자 세션으로 서버 저장본을 읽는다. 실제 경작지·작물·자연물·시설은 읽기 전용 보호 오버레이로 표시한다. 다른 편집 대상으로 이동할 때 초안을 먼저 저장하며 이전 공식/농장 초안도 목록에서 다시 열 수 있다.

`World.layout`만 지형/고정 배치/출입구의 설계도다. 실제 엔티티·인벤토리·보관함은 설계도와 별도로 유지한다. 개인 JSON 내보내기에는 농장 세션이나 서버 편집 키를 포함하지 않는다.

## 서버에 개인 설계도 보관 / 기기 이동

기존 Blueprint와 해시된 편집 토큰을 재사용한다. 처음 서버에 저장할 때에는 농장 소유자 세션이 필요하다. 농장이 없는 사용자는 개인 기기 초안을 먼저 만들고 그 설계도로 첫 농장을 생성할 수 있다.

서버 저장은 버튼을 눌렀을 때만 실행한다. 서버 초안 revision이 다르면 저장/생성을 거절한다. 소유자 세션으로 내 서버 목록을 조회하거나 설계도 ID와 전용 편집 키로 다른 기기에서 불러올 수 있다. 편집 키는 별도 보관 버튼으로 내보내며, 새 기기의 편집 대상 메뉴에서 ID/키를 입력한다. 농장 전체 세션을 설계도 전용 키처럼 내보내지는 않는다.

새 농장 화면은 공식 / 이 기기 개인 / 인증된 서버 설계도를 이름과 지형 미리보기로 표시한다. 이전 버전의 게시 설계도 선택은 명시적인 호환 항목으로 유지한다. 선택한 기기 설계도도 서버로 전송해 검증하고 실제 가족 저장본에 복사한다. 기존 농장 참가/이어하기는 기기 선택을 무시하고 Colyseus가 전송한 가족 레이아웃만 사용한다.

## 현재 농장 적용·복원

1. 농장 저장본 불러오기 → 지형/고정 배치 편집.
2. 모든 가족이 농장에서 나간 후 변경 미리보기 실행.
3. 서버가 저장 revision, 작물의 농사 가능 영역, 기존 시설, 자연물/재성장, 플레이어 위치 및 경로를 검사한다.
4. 충돌 위치·ID를 표시하고 변경을 거부한다. 자동 삭제나 자동 재배치를 하지 않는다. 기존 상호작용 배치물은 게임의 이동/회수 도구를 사용한다.
5. 검사 통과 시 PostgreSQL에 **전체 World 자동 백업**과 30분 유효한 서버 미리보기를 만들고, 실제 농장은 그대로 둔다.
6. 사용자 최종 확인 후 미리보기 ID를 적용한다. 서버는 권한·접속 잠금·원본 revision을 다시 검사하고 레이아웃과 새 고정 배치물만 반영한다.
7. 재접속하여 서버의 새 레이아웃을 사용한다.

Room의 `pg_advisory_lock(hashtextextended(farmId,2526))`와 동일한 키를 쓰는 트랜잭션 잠금이 미리보기·적용·복원을 보호한다. 실행 중인 Room이 있을 때 DB JSON만 바꾸는 경로가 없다. 적용은 revision 조건부 갱신과 checkpoint를 같은 트랜잭션에서 처리한다. 중복 적용 요청은 같은 결과를 반환한다.

백업 복원은 맵뿐 아니라 그 시점의 진행·아이템을 되돌린다는 경고와 최종 확인을 표시한다. 복원 직전 상태도 다시 백업하며 revision은 항상 증가한다. 가족 계정/세션 테이블이나 action receipt를 삭제하지 않는다. UI는 최근 30개 백업을 보여주며 저장된 백업을 자동 삭제하지 않는다.

플레이어 위치는 기존 World JSON의 member에 추가로 저장한다. 재접속 시 유효한 저장 위치를 복원하고, 기존 운반 중 보관함 위치 계약도 유지한다.

## 공식 게시 운영 권한

일반 농장 소유자·Blueprint 편집 키·클라이언트 개발자 설정은 공식 게시 권한이 아니다. Backend 환경변수 `FARM_OPERATOR_TOKEN_HASH`에 운영자가 정한 32자 이상의 비밀 키의 SHA-256 hex를 설정해야 한다. 원본 키는 편집기의 운영자 입력란에서 한 번만 사용하며 저장하지 않는다. 서버는 일정 시간 비교로 검사하고 기존 공식 revision과 최종 확인을 요구한다.

변수가 없으면 공식 읽기와 신규 생성은 정상 동작하며 **공식 게시만 거부**한다. 이번 배포는 운영자 비밀 키를 임의 발급하거나 기존 Railway 환경 설정을 변경하지 않는다.

## 지역·건물·NPC 확장

기존 지역별 맵 크기, 12개 편집 레이어, 등록 에셋 카탈로그, 시작점, 출입구, 이벤트, NPC 시간/경로를 그대로 사용한다. 새 지역을 추가해 출입구로 연결할 수 있다. 서버 검증은 없는 지역/시작점을 참조하는 출입구와 이벤트를 거부한다.

선택적 `WorldLayout.npcBindings`는 기존 NPC ID에 `homeMapId/homeObjectId`, `workMapId/workObjectId`, `role`, `shopId`를 연결하는 확장 메타데이터다. 지역/배치물 참조를 검증하고 입출력/저장/적용에서 보존한다. 이 필드는 향후 콘텐츠를 위한 기반이며 새 NPC·직업·상점 시뮬레이션은 추가하지 않았다.

## 검증

- 공식 API/편집기/신규 농장 레이아웃 일치, 다른 기기 Colyseus 상태 일치.
- 마을 지형과 기존 건물 위치 변경, 새 지역 양방향 출입구, NPC 경로/거주지 메타데이터가 신규 농장에 반영됨.
- 권한 없는 개인 설계도 사용/현재 농장 접근/공식 게시 거부, stale revision 거부.
- 접속 중 적용 거부, 경작지 충돌 거부, 원본 불변, 자동 백업, 중복 적용, 재접속, 전체 복원 검증.
- 휴대전화 브라우저에서 첫 농장 생성 전 개인 설계도 생성·복제·개명·삭제·자동 저장·등록, 새 농장 생성, 별도 기기 접속, 서버 저장, 현재 농장 불러오기 검증.
- 기존 단위/통합/편집기/모바일 조작 테스트 및 Typecheck/Build 확인. PostgreSQL 실검증은 기존 farm CI에서 동일 통합 테스트를 실제 DB로 실행한다.
- 로컬 스크린샷 환경에는 한글 폰트가 없으므로 글리프가 네모로 보일 수 있다. GitHub farm CI는 Noto CJK를 설치하여 동일 화면을 artifact에 보관한다.
