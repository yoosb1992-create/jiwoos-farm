# v2.8.1 — stable character parts

Starting commit: `e65299e892695e848ed5325e231a2e125981e038` on `feature/v2.7-world-editor-2`.

## Shimmer and alignment fixes

The previous compositor inferred head, skin, clothes and per-column foot bounds from RGB in every source cell. Differently painted/bobbed frames could classify the same anatomical region as a different dye channel. Non-default hair was mostly an overlay, leaving the source haircut underneath. The tool rig also overlaid the original, undyed palm. Walk cells 16 and 20 in the source atlas were shifted seven pixels above their other walking cells.

The new renderer uses 48 fixed, reviewed part masks, explicit head/foot/palm anchors and a small direction-based head compositor. Source-art magenta fringe pixels are removed during offline mask compilation. Skin, clothing and outlines have stable shaded palettes. The seven-pixel translation is corrected in the fixed masks. Body proportions transform skin, outline and garments together; the tool grip and recolored palm follow that same cosmetic transform. Movement and action animation continue to play; they were not frozen to hide defects.

`client/character-masks.ts` is a compact run-length encoding of the existing atlas poses, not a collection of appearance combinations. `scripts/compile-character-masks.py` contains the authored neck/hand regions and tool erasures and records the source SHA-256. Rebuild masks only when editing the source atlas, then inspect walking, tools and carrying. The original atlas and legacy action-source textures remain unchanged.

## Options and preview

- Idle on every editor entry; walk and run previews retained.
- Eight replacement hair silhouettes, independent of gender; front/back/side layers and directional ties.
- Male/female shoulder, waist and hip proportions plus different face outlines. No effect on movement, reach, collision or stamina.
- Seven skin tones; six eye shapes and six iris colors; five independent eyebrow, nose and ear options.
- Boots, sneakers, wellies and sandals, with independently selected shoe color and foot-anchored drawing.
- Height 70–145%, step 5%, default 100%. Height only changes the existing render transform. A fixed wooden ruler provides a 100% reference. The slider sits beside the full preview even on a small phone.
- Collapsible face magnifier crops the same composited frame shown in the full preview; it is not separate portrait artwork.

## Data and extension points

`Appearance.version = 2` has independent `eyeShape`, `eyeColor`, `eyebrowStyle`, `noseStyle`, `earStyle`, `shoeStyle` and `shoeColor` fields. Strict server parsing validates every option and the finite stepped height range. Version 1 remains accepted and migrates on read: its `shoes` color becomes `shoeColor`, its existing garment/hair/gender choices survive, and new parts receive defaults. Legacy short/normal/tall map to 90/100/110%; the old 112% tall value rounds to the supported 5% grid. Missing or malformed saved cosmetics fail safely to defaults without resetting the member or world.

Palette tokens remain stable. Optional `customColors` accepts only known channels and six-digit sRGB hex strings; its server validation already supports future RGB/HSV editors. Eyebrow color follows hair until an independent `eyebrowColor` override exists. No advanced color UI ships here.

`EAR_PARTS` defines per-direction polygons, attachment positions and skin/fixed tint policies. Eyes, brows and noses have their own registries. Future species can supply default appearance presets and extend these registries without replacing the renderer or restricting individual customization. No species, village or ability system is added.

The existing PostgreSQL world/member JSON and Colyseus appearance string remain the persistence/broadcast path. No schema migration, database recreation, resource replacement or gameplay-state reset is needed.

## Runtime costs

Head layers are reused across clothing and height edits; body layers are reused across head edits. Bounded caches retain at most 64 head combinations, 240 body-layer tiles and 48 dye palettes. Game textures are generated only for appearances seen in that scene. Height is excluded from texture identity. The network adapter reparses an appearance only when its serialized value changes.

Inactive texture banks retire after 30 seconds, with periodic sweeping even on cache hits. Textures referenced by live, hidden, carrying or tool objects are retained. Scene shutdown releases owned texture banks. There is no per-animation-frame canvas generation, RGB classification or full-image readback.
