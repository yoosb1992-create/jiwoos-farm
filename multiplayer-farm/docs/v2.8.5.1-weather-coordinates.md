## 날씨

이전 `random(seed + day)()`는 선형 합동 난수의 첫 출력만 사용해 인접한 날짜의 결과가 매우 비슷했다. `precipitationForDay`는 기존 `weatherRoll` 해시를 별도 스트림에서 사용한다. 강수 기준은 여전히 30%이며 날짜·농장 시드에 대해 결정적이다. 강우 종류·바람·천둥·번개 스트림은 유지한다.

판정은 `nextDay`에서만 바뀐다. 로드된 당일 계획/시각/수분은 재추첨하지 않는다. 겨울 강수는 눈, 나머지는 기존 4종 분포로 계획한다. 가랑비·일반 비·폭풍우는 종일, 소나기는 기존 제한된 시간 구간을 유지한다.

고정된 256개 시드(연속 시드와 넓게 분산한 시드 포함) 시뮬레이션:

| 기간 | 총 강수일 | 강수 비율 | 농장별 강수일 범위 | 연속 두 날 모두 강수 |
|---|---:|---:|---:|---:|
| 28일 | 2,155 / 7,168 | 30.06% | 1–14일 | 9.09% |
| 112일 | 8,639 / 28,672 | 30.13% | 21–48일 | 9.13% |
| 365일 | 28,031 / 93,440 | 30.00% | 75–135일 | 8.97% |

독립적인 30% 강수의 연속 두 날 확률은 9%다. 개별 농장의 짧은 기간 비율이나 연속 맑음에 인위적인 상한을 강제하지 않는다. 표본 중 365일 최장 맑음은 34일, 강수는 9일이었다. 자연스러운 드문 연속 날씨는 가능하다.

## 터치 및 작업 좌표

이전에는 y가 큰 스프라이트의 Bounds를 우선 선택했다. 높이가 52px인 아래쪽 작물의 투명 여백까지 위쪽 32px 밭에 겹쳐, 위쪽 칸 중앙을 눌러도 아래 작물을 선택할 수 있었다.

soil/crop/withered는 `floor(world / 32)`로 논리적 셀을 먼저 고르고 다른 셀의 작물 Bounds는 후보에서 제외한다. 시설·나무 등의 기존 Bounds 상호작용과 NPC 우선 판정은 유지한다. 화면→월드는 Canvas CSS rect와 Phaser 논리 크기를 사용하며, 역변환인 `screenPoint`에도 같은 CSS 배율을 반영한다. 고정 픽셀 터치 보정은 없다.

행동 버튼의 괭이도 넓은 자연물 조준 범위가 아닌 정확한 앞칸의 엔티티를 사용한다. 인접 작물이 빈 앞칸의 괭이 작업을 가로채지 않는다. 기존 `frontTile`, 서버 거리/앞칸 검증, 새 정지 입력 ACK와 방향 확인은 변경하지 않는다. 물주기, 자동 도구 선택, 시설 메뉴, 명시적 회수/운반은 그대로다.

## 작물 그림

공통 시각 지면은 **서버 타일 중심 x, 중심 y + 6px**다. 경작지 underlay와 저장 좌표는 타일 중심에 남는다. 생성형 40×52 텍스처의 지면 (20,44)와 원본 80×104 성숙 이미지의 지면 접촉 메타데이터를 각각 Sprite Origin으로 연결한다. 이후 추가된 nature 작물 그림도 같은 규칙을 따른다. 이미지의 투명 여백이나 잎 경계를 뿌리로 추정하지 않는다.

씨앗 빛은 본체의 위치·origin·크기를 공유한다. 그림 안의 지면 그림자도 본체와 함께 정렬된다. 이미지 로드 실패 시 대체 그림 역시 해당 origin에 맞춘다. 연결형 경작지, 젖은 색상, 모든 작물 ID·성장 단계·저장 엔티티 좌표는 유지한다. DB/schema 마이그레이션은 없다.

## 검증 범위와 운영

- 28/112/365일 분포·재현성, `nextDay` 계절 판정, 저장 계획 유지, 종일 강우와 소나기 구간.
- 네 방향에서 앞칸 경작·파종·물주기·수확·마른 작물 제거, 인접 타일 불변, 잘못된 앞칸 거절.
- 실제 터치/핀치 확대 후 인접 두 작물 중 위쪽 칸만 물주기, 새로고침 후 명시적 재접속과 좌표/수분 보존.

- 기존 Colyseus 날씨/수분 동기화·경쟁 수확·저장 후 방 재개 검사.

FAST/TARGETED/FULL 워크플로와 선택기는 수정하지 않는다. shared 및 클라이언트 진입점 변경이므로 기존 정책이 관련 단위·서버 통합·PostgreSQL·브라우저·빌드 산출물 검사를 선택한다. 전체 FULL, 변경 없는 legacy/lab, Docker 검사를 추가로 강제하지 않는다.

기존 Railway 프로젝트와 세 서비스를 유지한다. 대기 중인 Check Suites 두 건은 적용하지 않는다. 현재 배포는 CI 성공을 기다리는 게이트가 아니므로 Actions와 배포를 별도로 검증한다. 실제 Android 하드웨어/주소창 동작은 이 환경에서 직접 측정할 수 없으며 화면 크기·DPR·Canvas 위치 변화로 좌표 경로를 검사한다.
